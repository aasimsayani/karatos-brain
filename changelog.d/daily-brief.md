- Added the daily brief: each morning at `BRIEF_HOUR` (7 by default) on the store's clock (`STORE_TIME_ZONE`, America/New_York by default), the instance builds yesterday's brief and saves it once in the new `daily_briefs` table, so a restart never builds or sends the same day twice. The brief covers yesterday's sales, refunds and net by channel and system against the same weekday last week, the open findings of the payout, stock-count, waiting-customer and return-rate rules, connectors that failed, went stale, haven't run or aren't syncing, and the other open recommendations, highest impact first. Every figure cites the event ids and systems it was counted from. An instance with nothing synced says so instead of showing zeros. Store days run midnight to midnight locally, so they are 23 or 25 hours long when the clocks change. `GET /v1/brief?date=` reads any day up to today with the instance key; the support key is refused. Optional delivery posts each new brief once to an operator's `BRIEF_WEBHOOK_URL` (https only, a secret, off by default). Nothing is emailed or texted. See docs/daily-brief.md.
- The memory store can read events of given types in a time range (`eventsBetween`) and the latest one before a time (`latestEventBefore`), in memory and in Postgres.
