- Smile.io connector (`@karatos/connectors`): imports five years of loyalty customers and points transactions, then reads only what changed on each sync. Customers arrive as `loyalty.customer_updated`, as Yotpo's do, with their points balance, program state, VIP tier (named from the program's tier list), when it ends and how far they are from the next tier; points transactions arrive as `loyalty.points_changed`. It uses a merchant API key made with read scopes only and sends only GET requests; adjusting a customer's points is declared behind the write gate and turned down. No names, birthdays, referral links or transaction notes are kept, and emails become the same customer references custom forms, Klaviyo, Quo and Yotpo make. Turn it on with `smile_io` in `ENABLED_INTEGRATIONS`, `SMILE_API_KEY` and `CUSTOMER_REF_KEY`.
- Connector test kit: a Smile.io mock built from its developer docs, with customer, points transaction and VIP tier fixture builders.
