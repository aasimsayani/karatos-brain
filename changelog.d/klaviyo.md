- Klaviyo connector: reads profiles, lists and segments with their members, campaigns, flows, and five years of campaign and flow figures (sends, opens, clicks, conversions, revenue) one calendar year per report, then every change on the sync schedule, pinned to Klaviyo API revision 2026-10-15. Klaviyo can't be asked which scopes a private key holds, so read-only is enforced by allowlist: eight listed GET endpoints with checked parameters, and the two read-only reporting POSTs by exact path with a body the client builds itself. Pages follow `links.next` only when it continues the same request, and 429s wait out `Retry-After`. Profiles become references keyed with `CUSTOMER_REF_KEY`, including contact references made the same way custom forms makes them, so a Klaviyo profile lines up with a form submitter by email; no email addresses, phone numbers, names, locations or custom properties are kept. Turn it on with `klaviyo` in `ENABLED_INTEGRATIONS` and the `KLAVIYO_*` settings in `secrets/manifest.json`.
- `verifyKlaviyoWebhook` checks `Klaviyo-Signature` over the raw body and `Klaviyo-Timestamp` in constant time, with a five-minute window and the webhook id check, and `KlaviyoReplayGuard` handles each event once. Consent changes become `marketing.consent_changed`.
- Connector test kit: a Klaviyo mock built from Klaviyo's API reference, with sparse fieldsets, query-bound cursors and checked report bodies, and fixture builders for each record type.
- Nightly sandbox run: a Klaviyo check, which runs once `SANDBOX_KLAVIYO_PRIVATE_API_KEY` is set.
- Secrets manifest: `KLAVIYO_PRIVATE_API_KEY`, `KLAVIYO_CONVERSION_METRIC_ID`, `KLAVIYO_WEBHOOK_SECRET` and `CUSTOMER_REF_KEY`.
