- Slack connector (`@karatos/connectors`): imports five years of messages and threads from the channels the business's own Slack app is invited to, then reads each channel's last week and any thread with a new reply on every sync, and reads a newly joined channel five years back. Bot token only, with `channels:read`, `channels:history` and optionally `groups:read` and `groups:history`; the client checks the scopes Slack reports (`x-oauth-scopes`) on `auth.test` and every answer and stops on anything more, such as `chat:write`, and it sends only `auth.test` and three allowlisted conversation reads. Each Slack user becomes a keyed reference under `CORRESPONDENT_HASH_KEY`; files are counted, never fetched; message text is kept only for the channels in `SLACK_TEXT_CHANNELS`, with email addresses, phone and other long numbers, link paths and mentions taken out. Reads are paced under Slack's tiers, including the one-a-minute, 15-message limit for non-Marketplace apps (`SLACK_APP_DISTRIBUTION`), and 429s are waited out. `verifySlackWebhook` checks `X-Slack-Signature` with a five-minute window, and Events API deliveries map to the same events, so retries are duplicates. `post_recommendation` and `post_alert` are declared behind the write gate. The scheduled sync runs it when `slack` is in `ENABLED_INTEGRATIONS`, and the nightly sandbox run can check it against a developer sandbox workspace
