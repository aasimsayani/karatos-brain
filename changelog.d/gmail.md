- Gmail connector (`@karatos/connectors`): imports five years of message metadata, threads and labels from one mailbox, newest first, then reads label changes and deletions from the mailbox history, listing again when Gmail no longer has the history. The connection uses `gmail.metadata` only, and the client stops if a token holds any scope that could read bodies or change mail; it sends four allowlisted GETs with `format=metadata` and the From, To and Cc headers only. Bodies, attachments, subjects, snippets, display names and addresses are never kept: each address becomes a keyed correspondent reference (`CORRESPONDENT_HASH_KEY`, generated per instance), with the domain kept only for businesses, so vendor mail stays attributable. Label changes are stored as new versions. Reads are paced under Gmail's per-mailbox quota and rate limits are waited out. `draft_reply` and `apply_label` are declared behind the write gate. The scheduled sync runs it when `gmail` is in `ENABLED_INTEGRATIONS`, and the nightly sandbox run can check it against a test account. `gmail.metadata` is a restricted scope: outside one Workspace organization the app needs Google's verification, and a consent screen in Testing gives tokens that last seven days
