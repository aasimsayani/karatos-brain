- Documentation search. Each document the instance knows (the repository's docs shipped in the image, and one document per catalog integration with what it does, its settings and its vendor's changelog) is cut into passages of at most 800 characters under its headings, each with its source, heading path and the document's version, and a vector for each. The built-in embedder (`local-hash-v1`) hashes words and word pairs into 1,024 dimensions, so search needs no outside service or key. Only passages whose content hash changed are embedded again, documents that disappear are dropped, and the index lives in Postgres, so it answers straight after a restart. `GET /v1/docs/search?q=` (instance key only) returns the closest passages with their source and score, and "how do I" and "where is" questions to `/v1/ask` are answered from it. `Embedder` is the seam for a hosted model later; none is added. See docs/doc-search.md.
- Migration `20261128000002_doc_search.sql` adds `doc_chunks` beside the documentation registry, which gains `source` and `indexed_at`. Where the pgvector extension is available (Supabase) it is turned on, with a generated vector column and an HNSW index for the built-in embedder; where it isn't, search works out cosine similarity in SQL over the stored `real[]` vectors. Tests run both on PGlite, with and without its pgvector extension (`@electric-sql/pglite-pgvector`, a dev dependency).
- `GET /v1/support/status` reports `docSearch`: the embedder, whether a sync is running, and the last index sync's times, outcome and counts.
- The instance image ships `docs/` for the index (`DOCS_DIR` points elsewhere).
