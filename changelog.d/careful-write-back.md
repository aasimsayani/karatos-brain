- Careful write-back (`@karatos/core`): `SafeWriter` runs a proposed write to a client's system through every check before anything is sent: a safe declaration (draft, append or update; never delete), the instance policy, a per-integration circuit breaker, the action's input schema and limits, a named approver (only a draft may skip it, and instance settings can only raise it), an idempotency key, a daily cap per action (25 at most) and a fresh re-read that rejects the write as stale if the record changed. After the write it reads the record back; a mismatch is audited as unverified and turns off that integration's writes until a person clears them. Each attempt is audited once with the proposal key, approver, evidence and the before and after values of only the touched fields. `undoProposal` builds the reverse of a verified update, which goes through the same checks. No connector turns a write on yet
- Connector test kit: `assertWriteSafety` checks a write target rejects turned-off, mis-shaped, unapproved, stale and over-cap writes, catches a write that silently does nothing and sends a replay only once
- Docs: [careful write-back](docs/architecture/write-back.md) explains the checks for owners and developers; the security model's connector section describes them
