- Added support access: an optional `SUPPORT_API_KEY`, different from `INSTANCE_API_KEY` and compared the same constant-time way, that reaches only `GET /healthz`, `GET /v1/integrations` and a new `GET /v1/support/status`; every other route turns it down with 403. The status shows operational metadata only: instance name, organization id, version, uptime, applied migrations, retention days, enabled departments and integrations, each integration's missing setting names and last sync (times, mode, outcome, counts and its last error with emails, credentials, URL paths, key-shaped runs and long numbers scrubbed, capped at 200 characters), dead-letter counts by source and reason, and event counts by day, source and type (`?days=`, up to 90). Never payloads, ids, names, amounts, recommendation text or signal values. `npm run secrets:setup -- --purposes core,instance,migrations,support` generates the key. See the security docs for what database and host access still expose.
