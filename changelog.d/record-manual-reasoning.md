- Reasoning's last run now counts `POST /v1/reason` calls and survives a restart. A call is recorded with trigger `manual` on `GET /v1/support/status` and in the brief's and answers' "findings were last refreshed" sentence, and runs in line with scheduled runs: while one is in progress it waits for it, then runs its own pass, going before a queued scheduled run, and answers with its own results exactly as before. At startup the instance reads the latest `reasoning_runs` row, so findings no longer read as not run after a restart; that run shows as succeeded, with `trigger` and `measured` null since the table doesn't store them. With `REASON_SCHEDULE=off`, manual calls are still recorded and the brief says when one last succeeded.
