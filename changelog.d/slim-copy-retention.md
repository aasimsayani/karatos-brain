- Slim copy data retention: raw vendor data (event payloads, dead-lettered input, uploaded file contents) is cleared after `RAW_RETENTION_DAYS` (default 30, a whole number from 1 to 365), while entities, signals, recommendations, decisions, outcomes, memories, links, sync runs and audit rows are kept. Rows are never deleted: a cleared payload becomes a small tombstone and the row keeps its ids, idempotency key, SHA-256 and a source reference (source system, vendor record id and, when a connector declares one, an https link), so replays are still duplicates and provenance still resolves. Events can declare `sourceRecord`, `MemoryStore.getEvent` returns the source reference, and `purgeRawData` on both stores is idempotent, runs at start and daily, and records each run in a new `retention_runs` table with row-level security.
