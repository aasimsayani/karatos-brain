- Google Workspace and Drive connector (`@karatos/connectors`): walks the Drive folder a business shares (and any listed shared drives) for file metadata (names, types, folders, sizes and edit times from the last five years), then follows Drive's change feed for edits, moves, trashing and folders moved in; reads only the Sheets ranges listed in `GOOGLE_SHEETS_RANGES`, storing a new version when they change; and imports five years of appointments from the listed calendars, then follows Calendar's sync tokens, listing again on a 410. The connection holds only `drive.metadata.readonly`, `spreadsheets.readonly` and `calendar.events.readonly`, and the client stops if a token holds anything else (`drive.readonly` included) or lacks one it needs; it sends five allowlisted GETs with fixed `fields`, so file contents, owners, links, appointment titles, descriptions and meeting links are never fetched. Attendee and organizer addresses become correspondent references under `CORRESPONDENT_HASH_KEY`, the same as Gmail's. It shares Gmail's OAuth client with its own refresh token (`GOOGLE_WORKSPACE_REFRESH_TOKEN`). `create_document` and `create_calendar_event` are declared behind the write gate, and so is opening push channels (`watch_drive_changes`, `watch_calendar_events`), since a watch is a POST that creates state in the Google account; `googlePushVerifier` checks notifications by channel token in constant time, channel, resource, expiry, state and message number. The scheduled sync runs it when `google_workspace` is in `ENABLED_INTEGRATIONS`, and the nightly sandbox run can check it against a test account
